## 关键经验(可复用)
- **Secure Boot 开启时 `bcdedit /debug on` 会被拒**:错误"该值受安全引导策略保护,无法进行修改或删除"。
  解法:用 Sysinternals LiveKD(livekd64.exe -w),它不改 BCD、不关 Secure Boot,做只读内核快照,
  和本地内核调试等价(都只读),适合探索结构体/反汇编。
- **LiveKD 启动要点**:
  1. _NT_SYMBOL_PATH 必须配好(livekd 依赖符号解析内核结构)。
  2. windbg.exe 要在 PATH 里(或在 livekd 目录跑),否则 livekd 找不到调试器。
  3. setx 设的环境变量在当前 shell 不生效,要开新 shell 或在脚本里显式 $env: 设置。
  4. 首次启动慢——要从微软符号服务器下载 ntoskrnl PDB(几十 MB)。
- LiveKD 工具位置:`C:\Tools\LiveKD\livekd64.exe`(本机)。

## 后续(同日)- 沙箱成果观测方法
- 用户问怎么用 LiveKD+WinDbg 让沙箱成果可观测。给出完整观测方法:
  - **时序**:终端 A 先启动 broker+target(m2_demo --net hello_target),target 卡在 WaitForExit 活着;
    终端 B 管理员跑 start-livekd.cmd 抓快照 → target 被冻结在快照里。
    关键:必须用 hello_target 这种不会秒退的 target,否则快照里抓不到。
  - **定位 target**:dt nt!_EPROCESS 找 ImageFileName 偏移 → 按名字搜;或 !process -1 0 看当前进程(broker)。
    禁用 !process 0 0(LiveKD 下会崩,见 Pitfall 9)。
  - **五件套 ↔ EPROCESS 字段对照**:
    1. Token 裁剪(M0)→ EPROCESS.Token → !token <addr> 看 Privileges 应为空
    2. Job Object(M0)→ EPROCESS.Job → dt nt!_EJOB <addr> 看 LimitFlags 含 KILL_ON_JOB_CLOSE
    3. Mitigation(M1)→ EPROCESS.MitigationFlags → !mitigation <addr> 看位图
    4. Low IL(M1)→ Token Mandatory Label → !token 看 Integrity Level = Low(S-1-16-4096)
    5. AppContainer(M2)→ Token PackageSid + Capabilities → !token 看 PackageSid=S-1-15-2-...
  - 每步都把"用户态代码"和"内核字段"对上 = 沙箱成果可观测。
- 注意:EPROCESS.Token 是 EX_FAST_REF,低 4 位是引用计数,取真实地址要 & ~0xF。
