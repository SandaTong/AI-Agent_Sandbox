## 工作内容
- 用户用 WinDbg 探索 ntoskrnl 遇到两个坑,带用户走通 LiveKD 方案:
  1. `bcdedit /debug on` 报"该值受安全引导策略保护" → Secure Boot 阻止,改走 LiveKD 绕开。
  2. 方案一(LiveKD)环境搭建完成:
     - 配 `_NT_SYMBOL_PATH = srv*c:\symbols*https://msdl.microsoft.com/download/symbols`(用户级 setx)
     - 创建 `C:\symbols` 目录
     - 下载 Sysinternals LiveKD 到 `C:\Tools\LiveKD\livekd64.exe`
     - 用户机器已有经典版 WinDbg(`C:\Program Files (x86)\Windows Kits\10\Debuggers\x64\windbg.exe`)
       和 WinDbg Preview(`WinDbgX.exe`)
     - 启动 `livekd64.exe -w`(需把 WinDbg 路径加进 PATH,并设好 _NT_SYMBOL_PATH)
     - WinDbg 窗口已弹出,livekd64 + windbg 进程都在运行(首次拉符号较慢)

## 关键经验(可复用)
- **Secure Boot 开启时 `bcdedit /debug on` 会被拒**:错误"该值受安全引导策略保护,无法进行修改或删除"。
  解法:用 Sysinternals LiveKD(livekd64.exe -w),它不改 BCD、不关 Secure Boot,做只读内核快照,
  和本地内核调试等价(都只读),适合探索结构体/反汇编。
- **LiveKD 启动要点**:
  1. _NT_SYMBOL_PATH 必须配好(livekd 依赖符号解析内核结构)。
  2. windbg.exe 要在 PATH 里(或在 livekd 目录跑),否则 livekd 找不到调试器。
  3. setx 设的环境变量在当前 shell 不生效,要开新 shell 或在脚本里显式 $env: 设置。
  4. 首次启动慢——要从微软符号服务器下载 ntoskrnl PDB(几十 MB)。
- LiveKD 工具位置:`C:\Tools\LiveKD\livekd64.exe`(本机)。
