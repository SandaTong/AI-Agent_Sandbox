# 2026-08-10

## 工作内容
- 用户告知 M4 已完成。通读新增代码确认实现:
  - `core/injector.{h,cc}`:远程线程注入四件套(VirtualAllocEx + WriteProcessMemory + GetProcAddress(LoadLibraryW) + CreateRemoteThread)。
  - `third_party/minhook/`:MinHook 库(inline hook,改函数头几字节跳到钩子)。
  - `demo/sandbox_hook.cc` → `sandbox_hook.dll`:被注入的拦截垫片,DllMain attach 时 MinHook 钩 CreateFileW。
  - `demo/m4_demo.cc`:CREATE_SUSPENDED → InjectDll → ResumeThread,保证 hook 在 target 跑用户代码前装好。
- M4 本质:和 M0~M3 完全不同维度。
  - M0~M3:用户态配置内核机制(SRM/Job/EPROCESS),内核强制执行(被动)。
  - M4:broker 主动注入 DLL 到 target,在 target 内部 hook 敏感 API(主动,用户态拦截)。
  - 对应 Chromium sandbox 的 "interceptions" 机制。
- 关键踩坑:
  1. 强 mitigation(PROHIBIT_DYNAMIC_CODE / BLOCK_NON_MICROSOFT_BINARIES)和"自己注入 hook"冲突 → M4 精简版关掉这两项。
  2. hook dll 继承 target 权限不提权:钩子逻辑在 target 内存不受 IL 限制,但 IO 仍受沙箱约束。
  3. 日志路径用 %TEMP%(Low IL target 一定有写权限),不用 C:\sandbox_share(Medium IL 目录被拦)。
  4. 钩子里写日志必须用 trampoline(g_orig_CreateFileW)防递归。
  5. kernel32 同 session 基址相同,这是远程线程注入能成立的前提。
